# Content

Read before touching `content/`, `lib/content/`, star counts, Videos, the Profile, Achievements or Hobbies.

Techs, Tech categories, Projects, Experiences, Achievements, Hobbies and the Profile live as JSON documents in `content/` (`techs.json`, `tech-categories.json`, `projects.json`, `experiences.json`, `achievements.json`, `hobbies.json`, `profile.json`); uploaded assets (Project images in `public/images/projects/`, Achievement art in `public/images/achievements/`, Resume PDFs in `public/pdf/`) stay in `public/`. Edit them by hand or through the Admin. Pages obtain content only through the content catalog in `lib/content/` (Effect v4, server only, see ADR-0002):

- `schema.ts` — Effect Schemas for every document (Localized text with non-empty `en` and `fr`, Tech, Tech category, Project, Experience, Achievement, Hobby, Profile; asset paths only name a plain file of their folder: a Project image `/images/projects/<name>.(png|jpg|jpeg|webp|avif)`, an Achievement's art the same in `/images/achievements/` or a chibi pose `/images/chibi/<name>.(webp|png)`, a Resume `/pdf/<name>.pdf`, never a sub-folder or `..`, as the Admin commits uploads to `public<path>`) and `Content`, which adds the cross-document rules (a Tech is defined once, every referenced Tech exists). `DOCUMENT_PATHS` maps each kind to its file.
- `period.ts` — the `Period` schema (start `YYYY` or `YYYY-MM`; end the same or `"ongoing"`; end not before start) and the ordering by start, most recent first, ongoing first on equal starts (a year counts as its January). Shared by every kind that has a Period.
- `format-period.ts` — `formatPeriod(period, locale)`, the plain Period formatting function (month names per Locale, "Today" / "Aujourd'hui"); no Effect import, so components may use it. Tested in `format-period.test.ts`.
- `repository.ts` — the `ContentRepository` port (`head`, `read` at a revision, by default the current one, `commit` with optimistic revision); adapters `repository-local-filesystem.ts` (build time, read-only), `repository-github.ts` (the Admin: Git Data API with the Owner's token, one commit per save on `main`, text or binary files, reads at a commit sha through the contents API's `ref`, fast-forward only so a moved `main` is a `ContentConflict`; tested against a fake GitHub `fetch`) and `repository-in-memory.ts` (tests; keeps every revision readable, and `makeInMemoryRepository` also lists the commits made).
- `catalog.ts` — the `ContentCatalog` service: decodes and validates all documents, then returns ready-to-render data (`techCategories` with resolved Techs; `projects` ordered by Period, with resolved Techs, their Rarity and home page place, a `repository` only for open-source Projects (the Profile's GitHub link when the Project has none) and, for a Project's own repository, its live GitHub star count, omitted when zero; `experiences` ordered by Period; `achievements` and `hobbies` in stored order, the order the Owner gives them; `profile`; `videos` of the Profile's channel, most recent first, with only the latest marked `isNew` while under 30 days old, read with Effect `Clock`). These members return Localized texts with both Locales (what the Admin edits); public pages use `inLocale(locale)` instead, the same Tech categories, Projects, Experiences, Achievements and Hobbies with every descriptive text in that Locale (proper nouns and Video titles as they are), plus the Locale's `resume` and `featuredProjects`: the Projects with a `featured` place, by place (1 first; equal places keep their Period order), at most 3, shaped like `projects` (star counts are read for those only). Invalid content fails with `ContentInvalid`, naming file and location, which fails the build. Tested in `catalog.test.ts`, `catalog-locale.test.ts` and `catalog-videos.test.ts`; `content.test.ts` checks that `content/` itself is valid, that every Resume exists and that every Achievement's art exists under `public/`.
- `github-stars.ts` — the `GitHubStars` source, consumed only by the catalog: `layer` reads `stargazers_count` from the public GitHub REST API (unauthenticated; any failure is `GitHubStarsUnavailable`), `layerTest` serves fixed counts per repository link.
- `external-source.ts` — what the external sources share: `fetchExternalText` (fetch with `cache: "no-store"`, so responses never land in Next's Data Cache, which `next build` persists in `.next/cache` across deploys), and the `PageGeneration` reference with `orOnColdBuild(fallback)`: on a `"cold-build"` (set by `server.ts` during `next build`, from `NEXT_PHASE`) a failing source falls back (stars omitted, no Videos); otherwise (`"revalidation"`, the default) its failure fails the catalog.
- `youtube-channel.ts` — the `YouTubeChannel` source, consumed only by the catalog: `layer` reads the channel's public Atom feed (no API key; any failure is `VideosUnavailable`), `layerTest` serves fixed Videos per channel. The channel identifier is the Profile's `youtubeChannelId`.
- `server.ts` — what pages call (`getTechCategories(locale)`, `getProjects(locale)`, `getFeaturedProjects(locale)`, `getExperiences(locale)`, `getAchievements(locale)`, `getHobbies(locale)`, `getResume(locale)`, `getVideos()`, `getProfile()`; pages pass `await getLocale()`): plain async functions over a `ManagedRuntime`, so React code never imports Effect. `types.ts` re-exports the content types for components (type-only).

## Rendering content

Pages format Periods with `formatPeriod(period, locale)` and Video dates with next-intl's formatter, so both follow the Locale. A Tech is rendered only by `components/tech/TechBadge.tsx` (its `#rrggbb` colour, text colour from `lib/text-color-on.ts`).

An Experience's contract type is an identifier (`entrepreneurship`, `permanent`, `work-study`, `internship`); its label is an interface string under `Experiences.contractTypes` in the message dictionaries. An Experience may carry an `emoji` (non-empty, at most 8 UTF-16 units), shown before its company on the home page.

## Home page content

- **Rarity** (`common`, `rare`, `epic`, `legendary`) is required on every Project and Achievement: what kind of thing it is, set by the Owner, never a quality score. Its label is an interface string, like a contract type.
- A Project's optional `featured` is its place on the home page (a whole number from 1, 1 first); without it the Project is not featured. `getFeaturedProjects` returns at most 3.
- An Achievement (`achievements.json`) has a Localized `name` and `description`, a `year` (2000 to 2100), a Rarity, a `link` (a page of the site without Locale matching `^/[a-z0-9-]*(/[a-z0-9-]+)*$`, e.g. `/mdf-2025`, or an http(s) URL; pages localise a site path through the Routes) and its `art` (see asset paths above). `content.test.ts` checks every art file exists.
- A Hobby (`hobbies.json`) has a Localized `label` and a `pose` among `surf`, `skate`, `lol`, `coding`, `coffee`, `series`, `music`, the chibi avatar pose the home page shows with it; the stored order is the public order.

## Profile

The Profile is Lucas's public identity, defined once: social links (GitHub, LinkedIn, YouTube, Instagram), the YouTube channel identifier (the YouTube link must be that channel's `https://www.youtube.com/channel/<id>` URL), the Discord account identifier and one Resume per Locale (`asset` path under `public/`, `lastUpdated` as `YYYY-MM-DD`). Its consumers read it, nothing is hard-coded: the Locale layout passes it to the sidebar footer (social links) and Presence (Discord account), the home page shows the Locale's Resume and date, the contact page links LinkedIn, the Videos page links the channel. `content.test.ts` checks every Resume asset exists.

## Stars, Videos and revalidation

Star counts and Videos are never written by hand. The Projects and Videos pages (and any page calling `getFeaturedProjects`, which reads stars too) declare `revalidate = 86400` and `dynamic = "force-static"` (needed so the uncached external fetches keep them static): they are regenerated on every deploy and then once a day. When GitHub or the feed fails at runtime, `getProjects()` / `getVideos()` reject, so Next keeps serving the previous page; during `next build` stars are omitted and the Videos page shows its empty state, and the build does not fail. The catalog reads `content/` from `process.cwd()` at runtime too (revalidating pages, and every page's layout reads the Profile), so `outputFileTracingIncludes` in `next.config.ts` ships the folder with every page under `[locale]` (check `.next/server/app/[locale]/*/page.js.nft.json`).
